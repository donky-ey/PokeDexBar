## 포팅 방식 (SP1 과 동일 + UI 특칙)

SP1 의 절차 P(diff 정독 → 테스트 선이식 RED → `sed` 경로 치환 `git apply --reject` → 리젝트
수동 → GREEN → 영어 커밋 `(upstream #NNN)`)를 그대로 쓴다. 추가 규칙:

1. **PopoverView 헝크는 전부 수동을 각오한다** — 포크 팝오버는 게임 탭이 섞여 구조가 다르다.
   사용량 섹션(게이지·주/월 행)은 모양이 가까워 함수 단위로 자리를 찾는다.
2. **`Localization` 헝크는 ko/en/ja 3언어만** — 업스트림의 추가 언어 값은 버린다(포크 `L` 규약).
3. UI 상태 추가(표시 모드·페이스 설정)는 `UserDefaults` 키 이름을 업스트림과 동일하게 유지 —
   SP3 이후 포팅 diff 최소화.
4. 커밋되기 전 `find . -name '*.rej'` 청소 + **`git add -A` 금지 범위**: `AGENTS.md` 등 미추적
   로컬 파일(SP1 리뷰에서 실제로 밟은 함정 — `':!AGENTS.md'` 제외 패턴 유지).
5. 배치 경계(A~G 각 끝)에서 전체 스위트.

## 검증

- 배치마다 이식·자작 테스트 + 전체 스위트.
- UI 는 스크린샷 생성기 방식으로 실물 확인: 오프스크린 렌더로 ① 쿼터바(마커+6색, 사용/잔여
  모드 각각) ② 트렌드(스택) ③ 리캡 — 눈으로 확인 후 임시 렌더 테스트 삭제.
- 완료 후 Dev 빌드 교체 실측(팝오버에서 트렌드·리캡 열어보기 — 사용자 확인).
- **릴리스 메모**: SP2 는 `feat:` + `Sources/**/UI/` 변경이라 다음 릴리스에서 **신규 에셋 하드
  게이트**에 걸린다 — 리캡·트렌드·페이스가 담긴 스크린샷을 `assets/` 신규 파일로 추가해야
  하고, `ScreenshotGenerator` 의 `ScreenshotFixture` 에 사용량 시드(가짜 스냅샷) 확장이 필요할
  수 있다. README(en/ko/ja)·랜딩 기능 카드도 갱신 대상.
